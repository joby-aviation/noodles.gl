# Sub-plan 02: Machine-Readable Reference Surface

A stable, documented, public machine-readable surface for the operator reference and the `noodles.json` format, so any agent with HTTP can contextualize on Noodles.gl — no MCP server, no browser, no repo checkout required.

## Goals

- Stable URLs for: per-operator JSON, an operator index, examples, a docs index, raw markdown mirrors of every docs page, `llms.txt`/`llms-full.txt`, and a JSON Schema for `noodles.json`.
- One deploy path that owns the surface.
- A strict, versioned JSON Schema for project files, kept in sync with `NOODLES_VERSION` by CI.

## Non-goals

- The MCP server that consumes this surface (sub-plan 03).
- Changing the in-app assistant's content-hashed context bundles at `/app/context/*` — they stay as-is, internal and undocumented.

## Requirements

1. WHEN an agent fetches `https://noodles.gl/r/registry.json` THEN the system SHALL return an index of every registered operator with name, category, description, and URLs to its JSON and reference page.
2. WHEN an agent fetches `https://noodles.gl/r/ops/<kebab>.json` THEN the system SHALL return the operator's full schema (inputs with type/default/options, outputs) and, once sub-plan 01 lands, the hand-written Remarks markdown.
3. WHEN an agent fetches any docs page URL with `.md` appended THEN the system SHALL return the raw markdown.
4. WHEN a project file declares `"version"` not equal to the current `NOODLES_VERSION` THEN validation against the published JSON Schema SHALL fail (and the schema `$id` SHALL be a stable URL).
5. WHEN `main` is deployed THEN the entire surface SHALL be regenerated by a single workflow (`deploy-docs.yml`), and no second workflow SHALL publish to the site.

## Verified groundwork

- zod is v4 (`^4.3.6`) — native `z.toJSONSchema()`, no `zod-to-json-schema` dependency needed.
- `migrate-schema.ts` uses Vite-only `import.meta.glob`; runtime migration code cannot be imported into plain Node scripts without a build shim. `NOODLES_VERSION` = 14, derived from `src/noodles/__migrations__/`.
- Edge id format: `` `${source}.${sourceHandle}->${target}.${targetHandle}` `` (`src/noodles/utils/migration-utils.ts:7-9`).
- The existing `NodeSchema`/`EdgeSchema` in `src/ai-chat/types.ts` are modification-payload schemas — too loose for a project file.
- `website/static/llms.txt` exists, hand-written. Content bundles already deploy to `noodles.gl/app/context/` but with content-hashed filenames behind a manifest — designed for the in-app loader, not stable URLs.
- `deploy-docs.yml` (Pages artifact flow) already runs `generate:context`; `generate-context.yml` (peaceiris gh-pages branch push) is a second, mechanically conflicting publish path.

## Design

### D1. URL map

All generated by a new `noodles-editor/scripts/generate-reference.ts` into `website/static/` (gitignored), run in deploy before `build:website`, except where marked *checked in*.

| URL | Content |
|---|---|
| `https://noodles.gl/llms.txt` | Hand-written head + generated sections between `<!-- BEGIN/END GENERATED -->` markers: all docs pages, all operator reference pages, registry/schema URLs. File is checked in; generator rewrites the marked section; CI `--check`. |
| `https://noodles.gl/llms-full.txt` | Concatenation of all docs + operator reference markdown. |
| `https://noodles.gl/r/registry.json` | `{version, generated, commit, operators: [{name, kebab, displayName, category, description, jsonUrl, docsUrl}], categories, fieldTypes: string[]}` |
| `https://noodles.gl/r/ops/<kebab>.json` (~130) | Full operator: inputs (type/default/options), outputs, plus `remarks` (markdown extracted from `docs/reference/operators/<kebab>.md`), `examples` (ids of example projects using this op), `docsUrl`. |
| `https://noodles.gl/r/examples.json` | Index of the example projects: id, name, description, tags, layerTypes, url. |
| `https://noodles.gl/r/examples/<id>.json` | `{id, name, readme, project}` — project with the same large-data stripping as the context bundles. |
| `https://noodles.gl/r/docs.json` | Docs page index: `{pages: [{id, title, url, mdUrl, headings}]}`. |
| `https://noodles.gl/schema/noodles-project.schema.json` | JSON Schema, `$id` = this URL; version alias `noodles-project.v14.schema.json`. **Checked in** at `website/static/schema/`. |
| `https://noodles.gl/<docPath>.md` | Raw markdown mirror of every page under `docs/` (e.g. `/users/getting-started.md`, `/reference/operators/scatterplot-layer.md`). No collision with Docusaurus HTML output — pages emit `<path>/index.html`. |
| `https://noodles.gl/app/context/*.json` | Unchanged, internal (in-app assistant only). |

Rationale for the combination: shadcn-style per-item JSON gives one fetch per operator with everything embedded; `.md` mirrors match the emerging convention (Anthropic/Vercel docs sites); `llms.txt` is the discovery entrypoint that links the rest.

### D2. JSON Schema for `noodles.json`

- New `noodles-editor/src/noodles/utils/project-schema.ts`: a **strict, hand-authored zod schema** for `NoodlesProjectJSON` — `version: z.literal(NOODLES_VERSION)`, node shape (id as Unix path, type in `opTypes`… as far as zod can express statically), edge shape with `^out\.` / `^par\.` regexes on handles, passthrough for `timeline`/`viewport`/unknown keys. Unit test validates every project under `src/examples/`.
- New `noodles-editor/scripts/generate-project-schema.ts` emits it via `z.toJSONSchema()`; npm script `generate:schema` with `--check`. Output **checked in** (changes rarely, should be code-reviewed, and is fetchable from raw.githubusercontent as a bonus).
- CI: `generate:schema -- --check` step in `.github/workflows/test.yml`. A new migration changes `NOODLES_VERSION`, the check fails, the schema gets regenerated in the same PR — that's the sync mechanism.
- Prose accompanying the schema (and the authoring guide it pairs with, sub-plan 03) is the `noodles.json` **file-format spec** — the only documents written in RFC 2119 register (capitalized MUST/SHOULD/MAY for interoperability contracts: `version`, node/edge shapes, `out.`/`par.` handle prefixes, the edge-id formula). See sub-plan 01 D5 for the scoping rule.

### D3. Deploy-path cleanup

Delete `.github/workflows/generate-context.yml`. `deploy-docs.yml` becomes the single owner: `generate:context` → `generate:reference` → `build:all`. (Also add `generate:reference` to `build:all:cloudflare`.)

### D4. Generation details

- `generate-reference.ts` reuses `parse-operators.ts` + `categories.ts`; example-indexing logic shared with `generate-context.ts` is extracted into `noodles-editor/scripts/lib/` rather than duplicated.
- Remarks extraction: read `docs/reference/operators/<kebab>.md`, take the content between `## Remarks` and the next `##` heading. If the directory or section is absent (sub-plan 01 not yet landed, or skeleton page), emit the operator JSON without `remarks` — the surface ships first and upgrades automatically.
- Gitignore `website/static/r/`, `website/static/llms-full.txt`, and the mirror directories; keep `llms.txt` and `schema/` tracked.

## Implementation steps

1. Delete `.github/workflows/generate-context.yml`.
2. Add `project-schema.ts` + tests; add `generate-project-schema.ts` + `generate:schema` script; commit the schema output; wire `--check` into `test.yml`.
3. Write `generate-reference.ts` + `generate:reference` script; extract shared helpers from `generate-context.ts` into `scripts/lib/`; update `.gitignore`.
4. Rewrite `website/static/llms.txt` into hand-head + generated-section form.
5. Wire `deploy-docs.yml`: add the `generate:reference` step after `generate:context`, before `build:all`.
6. After sub-plan 01 lands: confirm Remarks embedding and reference-page mirroring activate (conditional code path, no changes needed).

## Verification

1. `npm run generate:reference && npm run generate:schema -- --check` locally.
2. `npm run build:all`, then `npx serve website/build` and curl: `/r/registry.json`, `/r/ops/scatterplot-layer.json`, `/schema/noodles-project.schema.json`, `/llms.txt`, `/users/data-guide.md`.
3. Validate `src/examples/nyc-taxis/noodles.json` against the published schema with Ajv (expect pass); mutate `version` to 13 (expect fail).
4. After deploy: repeat the curls against `https://noodles.gl`.
