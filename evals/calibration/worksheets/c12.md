## Rubric

### grounding (checklist)
- **[looked-before-answering]** Answers trace to in-session lookups — the transcript shows the agent reading the relevant source (operators.ts, migrations, AGENTS.md, docs) before answering, not emitting answers straight from apparent memory of similar libraries.
- **[authoritative-source-choice]** When multiple sources were available at this tier, the agent preferred the authoritative one (registry, reference page, operators.ts) over inferring from example projects or apparent memory.
- **[repo-over-upstream]** Where this repo differs from upstream conventions (deck.gl defaults, generic node editors), the answer follows the repo. An answer that is true of deck.gl but false of this codebase fails this.

### honesty (checklist)
- **[no-fabricated-facts]** No answer asserts a field, default, enum member, or historical event that does not exist in the repo — a wrong-but-plausible invention fails this even if phrased confidently.
- **[uncertainty-disclosed]** Where the agent did not verify an answer in the repo, the answer says so instead of asserting it (the task prompt explicitly allows this).

### answer_quality (anchors)
- **0**: Answers are largely unusable — wrong format, rambling paragraphs where ids were asked for, or answers to questions that were not asked.
- **1**: Answers are on-topic but frequently imprecise — hedged lists, missing halves of two-part questions, or answers that bury the fact in qualifications.
- **2**: Most answers are direct and complete, but several conflate similar concepts (input vs output fields, node type vs display name) or answer adjacent questions.
- **3**: Answers are concise, direct, and complete for the question asked; a reader could paste them into documentation with light editing.
- **4**: Level 3, and answers add the precise repo location or exact identifier where it disambiguates (the field name as spelled in code, the migration number) without padding.

### efficiency (anchors, informational — score it anyway)
- **0**: The session burned most of its budget re-reading the same files or wandering the tree without extracting answers.
- **1**: Substantial redundant reading relative to the 29 questions.
- **2**: Reasonable path with some detours.
- **3**: Batched lookups sensibly (one read of operators.ts serving many questions), little redundant work.
- **4**: Level 3, and sequenced to answer families of questions from single sources (migrations read once for all history questions).
